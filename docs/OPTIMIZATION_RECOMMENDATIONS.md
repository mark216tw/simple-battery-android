# APP 介面與功能優化建議

## 文件目的

本文件依據目前程式碼與使用指南整理「簡單電池」的介面及功能優化方向，目標是提升資訊正確性、操作一致性、無障礙體驗與背景更新效率。

檢視基準：`1.0.0-prerelease.3`

優先級定義：

| 優先級 | 定義 |
| --- | --- |
| P0 | 可能造成錯誤資訊、操作誤解、隱私落差或不必要耗電，建議優先修正 |
| P1 | 明顯改善可用性、穩定性及維護性，建議近期完成 |
| P2 | 增加產品價值或進一步改善體驗，可排入後續版本 |

## 現況摘要

APP 已提供即時手機電量、充電資訊、外觀設定，以及手機電量、電池溫度與藍牙裝置電量三種桌面小工具。整體設計簡潔，且沒有網路權限，符合低干擾與重視隱私的產品方向。

目前較需要改善的部分集中在：

- 部分介面說明與實際操作不一致。
- 無法取得資料時，部分狀態可能被顯示成正常數值或模糊狀態。
- 藍牙權限、裝置與資料狀態缺少完整引導。
- 小工具背景更新與繪製有減少喚醒及重複工作的空間。
- 文字資源、語意標記與大字體適配仍不完整。

## 介面優化建議

### UI-01 修正小工具操作說明與返回行為

優先級：P0

設定頁目前寫著「點擊已加入的小工具可再次調整」，但點擊小工具實際上會開啟 Android 電池或藍牙設定。小工具設定頁的「返回」則會啟動 APP 主畫面，與一般返回操作的預期不同。

建議方案：

- 將說明改為「長按小工具，使用 Launcher 提供的編輯功能重新設定」。
- 將小工具設定頁的返回操作改為標準向上或系統返回行為。
- 有未儲存變更時顯示確認提示，清楚區分「放棄」與「完成」。
- 保持 APP 內說明與 `docs/USAGE.md` 一致。

預期效益：降低誤操作與設定流失，讓導航符合 Android 使用習慣。

### UI-02 完善藍牙權限與空狀態引導

優先級：P0

目前僅區分已授權、未授權及無已配對裝置，沒有處理拒絕後說明、永久拒絕、藍牙關閉或裝置尚未配對等情況。

建議方案：

- 在首次要求權限前，簡短說明用途與不會收集或上傳資料。
- 權限被拒絕時提供再次要求權限的理由。
- 權限被永久拒絕時提供「前往 APP 設定」按鈕。
- 藍牙關閉時提供「前往藍牙設定」操作。
- 沒有配對裝置時，提供配對指引及重新整理功能。
- 未選擇裝置時，在停用的「完成」按鈕附近顯示原因。

預期效益：減少使用者卡在設定流程，並提高藍牙小工具設定成功率。

### UI-03 正確呈現未知與無法取得的電池狀態

優先級：P0

當系統無法提供容量時，目前可能回退顯示 `0%`；未知、未充電等狀態也可能被統一顯示為「使用電池中」。這會讓「沒有資料」看起來像真實電量或正常狀態。

建議方案：

- 將電量改為可空值，無資料時顯示 `--%` 與「無法取得電量」。
- 分開顯示「充電中」、「已充滿」、「使用電池中」、「已接上電源但未充電」及「狀態未知」。
- 資料暫時不可用時保留版面，不以假數值填補。
- 為 TalkBack 提供完整狀態描述，而非只讀出數字。

預期效益：避免誤導，提升資訊可信度。

### UI-04 加強無障礙與大字體支援

優先級：P1

目前多個選項以文字 `✓` 表示選取，部分按鈕強制單行，色相滑桿缺少可理解的名稱；小工具採用點陣圖，內容描述也沒有反映類型與目前數值。

建議方案：

- 為主畫面電量表、狀態、色相滑桿與所有選項增加語意資訊。
- 使用 `selected`、`stateDescription` 等語意，不只依賴顏色或 `✓`。
- 支援至少 200% 系統字體，允許模式選項換行或改用自適應排列。
- 將充電符號改為向量圖示，提供一致的視覺與朗讀描述。
- 依小工具類型與內容設定可理解的 `contentDescription`。
- 以 TalkBack、鍵盤或 Switch Access、深淺色及高對比情境驗證。

預期效益：讓視力、操作能力或字體需求不同的使用者也能完整操作。

### UI-05 讓小工具預覽反映真實設定與狀態

優先級：P1

藍牙小工具預覽固定顯示 `85%` 與「藍牙裝置」，無法確認所選裝置及實際狀態；三種 Launcher 小工具也共用相同預覽圖。

建議方案：

- 藍牙預覽顯示所選裝置名稱。
- 有可用快取時顯示實際電量，否則明確標示「預覽」或呈現等待、離線等狀態。
- 為手機電量、溫度與藍牙電量建立不同的 Launcher 預覽圖。
- 預覽長裝置名稱、透明背景、最小尺寸與最大字級下的裁切效果。

預期效益：使用者在儲存前可預測桌面上的實際結果，並更容易在小工具清單辨識類型。

### UI-06 強化健康與溫度異常提示

優先級：P1

主畫面目前以相同樣式顯示所有健康狀態，只有溫度小工具在 40°C 以上使用警示色。

建議方案：

- 過熱、過冷、過電壓或需更換時，以警示色、圖示及簡短文字突出顯示。
- 避免只用顏色區分，加入可朗讀的警示內容。
- 對高溫提示採中性安全文案，例如建議暫停高負載或移除不利散熱的環境，不提供無法保證的診斷。

預期效益：讓重要異常資訊比一般狀態更容易被注意。

### UI-07 提升小工具新增與相容性說明的可發現性

優先級：P2

目前設定頁只以文字說明如何新增小工具，藍牙相容性限制也主要位於使用指南。

建議方案：

- 在支援的 Launcher 與 Android 版本使用 widget pinning API 提供「新增小工具」。
- 加入「藍牙裝置支援說明」，解釋標準 BLE Battery Service 與廠商私有協定限制。
- 在設定頁提供使用指南、隱私說明及版本資訊入口。
- 提供還原預設外觀設定的操作，執行前要求確認。

預期效益：降低功能探索成本，並在設定前建立正確期待。

### UI-08 將所有使用者文字移至資源檔

優先級：P1

多數文字目前直接寫在 Kotlin 與 Manifest 中，增加多語系、文案一致性及無障礙測試的維護成本。

建議方案：

- 將所有畫面、狀態、錯誤、權限說明與小工具名稱移至 `strings.xml`。
- 使用格式化資源處理百分比、版本、時間與裝置名稱。
- 統一「APP」、「小工具」、無資料與錯誤狀態用語。
- 保留繁體中文為預設語系，再依產品需求加入英文等語系。

預期效益：降低文案分歧，並為多語系與自動化測試建立基礎。

## 功能優化建議

### FN-01 減少小工具背景耗電與重複繪製

優先級：P0

目前週期工作在建立後不會於所有小工具移除時取消；前景中的每次電池廣播也會更新所有手機與溫度小工具。點陣圖繪製若頻繁執行，會偏離低耗電目標。

建議方案：

- 只在至少存在一個小工具時排程週期工作，最後一個小工具移除後取消工作。
- 合併短時間內重複的電池或系統事件，並只更新受影響的小工具類型。
- 比較關鍵資料是否改變，無變化時略過點陣圖重繪。
- 將接收器中的較重工作交由安全的非同步流程，正確管理完成時機。
- 量測更新次數、執行時間與耗電，確認最佳化效果。

預期效益：降低背景喚醒、CPU 與記憶體使用量。

### FN-02 修正 APP 快捷選單的系統設定 Intent

優先級：P0

動態快捷選單先解析電池設定 Intent，之後又將 action 改為 `ACTION_VIEW`，可能使已解析的系統元件收到不相符的 action，並在部分 OEM 裝置失效。

建議方案：

- 保留 `SystemSettingsIntents.createIntent()` 最終解析成功的 action 與 component。
- 在不同 API 與至少兩種 OEM 裝置驗證快捷選單能正確開啟電池設定。
- 若沒有可處理的電池頁面，維持退回一般系統設定的策略。

預期效益：提高快捷功能在不同裝置上的可靠性。

### FN-03 修正藍牙快取新鮮度與狀態語意

優先級：P0

目前藍牙快取沒有時間戳記，連線裝置可能長期使用舊值；讀取流程也會將不支援轉成「等待電量」，導致畫面與使用指南定義不一致。

建議方案：

- 為快取加入讀取時間與來源，設定合理有效期限。
- 快取過期時觸發新讀取；讀取期間可保留舊值但標示更新中或最後更新時間。
- 明確定義並保留「離線」、「等待電量」、「不支援」、「需要權限」與「未設定」。
- 避免 Manifest 與動態接收器在程序存活時重複處理同一事件。
- 對連線、逾時、無 Battery Service、讀取失敗與權限撤銷建立測試。

預期效益：避免顯示過期資訊，讓錯誤狀態可被理解與排除。

### FN-04 保存畫面與小工具設定中的暫存狀態

優先級：P1

主畫面的設定目的地，以及小工具設定中的色相、字級與裝置選擇，在 Activity 重建後可能回到初始值。

建議方案：

- 保存 APP 目前目的地，旋轉或程序重建後仍停留在設定頁。
- 使用 `ViewModel` 與 `SavedStateHandle` 保存未完成的小工具設定。
- 權限返回、切換至藍牙設定再回來時重新檢查權限及裝置清單。
- 將藍牙小工具儲存後更新改為生命週期安全或可持續的工作。

預期效益：避免設定內容意外遺失，提升旋轉與跨頁流程穩定性。

### FN-05 補齊電池來源、健康與估算資料處理

優先級：P1

目前未標示 dock 電源，部分健康狀態會落入「未知」；估算功率雖有標示「估算」，但未說明它是以裝置回報的電池電壓與電流計算，並非充電器輸入功率。

建議方案：

- 支援系統提供的 dock 電源及所有可辨識健康狀態。
- 對零值、負值、unsupported sentinel 與異常 scale 定義一致規則。
- 在介面或說明中註明功率屬於電池端估算，實際充電器功率可能不同。
- 為來源、健康、電流、功率與剩餘時間格式化建立單元測試。

預期效益：提升跨裝置資料正確性，避免使用者誤解估算數據。

### FN-06 讓備份行為與隱私說明一致

優先級：P0

Manifest 目前允許 Android 備份，但隱私文件表示解除安裝會清除所有本機資料。系統備份可能還原偏好設定、藍牙位址或快取，兩者存在落差。

建議方案：

- 優先排除藍牙位址、藍牙電量快取等裝置相關資料，不納入備份。
- 依支援 API 設定 backup 與 data extraction rules。
- 若保留設定備份，更新隱私文件，清楚說明 Android 系統可能備份與還原哪些資料。
- 驗證解除安裝、重新安裝與系統還原後的實際行為。

預期效益：避免隱私聲明與實際平台行為不一致。

### FN-07 集中管理小工具更新流程

優先級：P1

更新觸發目前分散在多個 Provider、Receiver、Worker 與主畫面中，容易產生重複更新、不同步或難以測試的問題。

建議方案：

- 建立單一小工具更新協調器，統一處理事件、目標類型與更新原因。
- 將電池觀察與格式化邏輯抽成可測試元件，供主畫面及小工具設定預覽共用。
- 記錄不含敏感資料的更新原因與耗時，僅供本機除錯。
- 為排程、取消、事件合併與指定類型更新建立測試。

預期效益：降低重複程式碼與回歸風險，讓效能最佳化更容易驗證。

### FN-08 自動更新藍牙裝置清單

優先級：P1

已配對裝置清單目前只在權限布林值改變時重新計算。使用者若前往系統設定配對裝置再返回，清單可能仍是舊資料。

建議方案：

- 在畫面恢復前景、藍牙狀態改變及配對狀態改變時重新載入清單。
- 保留仍有效的選取項目；裝置已解除配對時提示重新選擇。
- 提供手動重新整理，並顯示載入或錯誤狀態。

預期效益：避免使用者必須重開設定頁或 APP 才能看到新裝置。

### FN-09 提供可選的電量與溫度通知

優先級：P2

APP 目前以主畫面與桌面小工具為主，使用者必須主動查看狀態。可考慮加入完全由使用者啟用的提醒功能。

建議方案：

- 支援自訂低電量、充滿及高溫門檻。
- 預設關閉，啟用時說明通知權限與背景限制。
- 對同一狀態設定冷卻時間，避免重複通知。
- 不為此功能加入網路、帳號或雲端依賴。

預期效益：在不改變隱私定位的前提下增加實用性。

### FN-10 顯示小工具資料更新時間

優先級：P2

Android 省電策略可能延後 WorkManager，藍牙資料也可能來自快取。只顯示數值時，使用者無法判斷資料是否仍具時效性。

建議方案：

- 將「最後更新時間」設為可選的小工具次要資訊。
- 資料超過有效期限時，以淡化樣式或狀態文字提示。
- 不增加高頻更新；時間顯示應配合既有更新事件改變。

預期效益：提升資料透明度，降低把舊值當成即時值的風險。

## 建議執行順序

第一階段應先完成 UI-01、UI-02、UI-03、FN-01、FN-02、FN-03 與 FN-06，修正誤導、隱私落差及耗電風險。

第二階段完成 UI-04、UI-05、UI-06、UI-08、FN-04、FN-05、FN-07 與 FN-08，提升可用性、穩定性與可維護性。

第三階段再依使用者回饋評估 UI-07、FN-09 與 FN-10，避免在核心可靠性改善前擴張功能。

## 驗證原則

- 至少覆蓋 Android 8、Android 12 與目前 target API 的代表性裝置或模擬器。
- 在不同 Launcher 驗證新增、重新設定、縮放與移除小工具。
- 驗證淺色、深色、200% 字體、TalkBack 與螢幕旋轉。
- 使用實體藍牙裝置驗證支援、不支援、離線、權限拒絕及快取過期狀態。
- 透過單元測試覆蓋資料轉換與狀態映射，透過 UI 測試覆蓋主要設定流程。
- 以背景工作執行次數與耗電量測確認最佳化，而不只確認功能可運作。
